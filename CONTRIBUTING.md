# Contributing

## Contribution Standards

- Keep changes scoped and reviewable
- Prefer clear commits over broad refactors
- Preserve the established ZeroChill Co visual language
- Document user-facing changes in plain language

## Coding Standards

- Keep dependencies minimal
- Avoid TypeScript unless explicitly required
- Prefer reusable components over duplicated UI
- Use accessible contrast and semantic markup
- Keep SVG and CSS the first choice for presentation assets

## Design Consistency

- Maintain the obsidian / charcoal / crimson palette
- Keep the terminal-inspired typography and spacing system
- Avoid generic SaaS layouts, pastel surfaces, and soft rounded visuals
- Preserve industrial grid behavior and tactical separators

## Documentation Rules

- Write in precise infrastructure language
- Avoid hype, metaphor overload, or startup sales copy
- Separate public brand copy from internal operator notes
- Keep docs aligned with the current implementation, not future speculation

## Workflow

1. Open an issue or describe the change clearly.
2. Implement the smallest useful slice.
3. Verify with `npm run build`.
4. Include notes about any assumptions or deployment impact.
